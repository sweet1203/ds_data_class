정조의 부탁, 다산의 한 장
1789년 조선의 왕 정조는 현륭원(사도세자의 무덤, 지금의 융릉)에 7년 동안 나무를 심었어요. 8개 고을에서 심은 나무의 기록은 수레에 실으면 소가 땀을 흘릴 만큼 많았지요. 정조가 「고을별로, 종류별로 몇 그루인지 한 권의 책으로 명확하게 정리해 보라」고 하자, 다산 정약용은 그 많은 기록을 종이 한 장에 담아 왔어요.

오늘은 흩어진 데이터를 모아 데이터셋을 만들어 보고, 데이터셋이 아주 많아지면 왜 데이터베이스와 데이터베이스 관리 시스템이 필요한지 알아봐요.

중단원 도입 · 2. 데이터의 저장과 활용

이 중단원에서는 데이터를 체계적으로 저장하고 정리하는 방법을 배워요. 중단원 핵심 질문은 「데이터를 효율적으로 관리하는 방법과 그 필요성은 무엇일까?」예요.

📣 세상을 바꾸는 데이터 · 임진왜란 1년 전, 왕실에서 벌어진 토론 (32~33쪽)

일본을 다녀온 두 신하가 왕에게 정반대의 보고를 올렸어요. 왕은 혼란스러웠어요. 「동시에 보고 들었는데 어째서 말이 서로 다른 것이냐?」

⚔️

황윤길

「전하, 일본은 우리나라를 반드시 침략할 것이옵니다.」

도요토미 히데요시의 군사력과 준비 상황을 지켜보며 침략 의도를 파악했어요.
🍵

김성일

「아니옵니다 전하. 일본은 우리나라를 침략할 생각이 없어 보였사옵니다.」

도요토미 히데요시의 친절한 겉모습을 보고 전쟁의 의도가 없다고 판단했어요.
메모를 쓴 뒤에 교과서 33쪽의 정리 보기

두 신하 모두 자신의 직관과 단편적인 정보에 기대어 판단했어요. 침략을 내다본 황윤길도, 눈으로 본 사실 말고도 관련 데이터를 충분히 모으고 분석했다면 더 합리적인 판단을 내릴 수 있었을 거예요. 중요한 결정은 직감보다 구체적인 근거와 데이터를 바탕으로 해야 해요.

데이터 과학으로 문제를 바라본다면? (34쪽)

매일 아침 우리는 휴대폰으로 메시지를 확인하고, 인터넷에서 물건을 주문하고, 은행 앱으로 계좌 잔액을 조회해요. 이런 메시지, 쇼핑 내역, 금융 정보는 모두 체계적으로 관리되고 있어서 언제든 필요한 정보를 빠르게 확인할 수 있어요.

데이터와 데이터셋은 어떤 관계일까?

교과서 35~36쪽 · 데이터, 데이터셋, 정형·비정형 데이터셋

쉽게 말하면「어느 날, 어느 고을에, 무슨 나무를, 몇 그루 심었다」 같은 낱낱의 기록 하나가 데이터예요. 이런 기록을 분석하기 쉽게 기준을 정해 표로 모으면 데이터셋이 돼요. 데이터는 개별적인 정보의 단위이고, 데이터셋은 이를 모은 구조화된 집합이에요.

📜 다산은 이렇게 정리했어요 (그림 Ⅰ-4 · Ⅰ-5를 다시 그림)

현륭원에 나무를 심을 때마다 기록이 남았지만, 셀 수 없이 많은 공문서의 무더기일 뿐이었어요. 다산은 공문을 8개의 고을별로 분류하고, 고을별 묶음을 월별로 정렬해 연도별 표로 옮겨 적었어요. 이렇게 요약한 8개의 표를 다시 1개의 표에 옮겨 적었지요.

다산이 한 일이 바로 데이터에서 데이터셋을 만들어 낸 것이에요. 처음 공문 형식으로 기록된 문자와 숫자의 값들이 데이터이고, 이를 고을별·나무 종류별 수치를 연도별로 정리한 표가 데이터셋이에요. 그런데 정조가 알고 싶었던 것은 지난 7년 동안 가장 많은 나무를 심은 고을이었어요. 그래서 다산은 데이터셋1을 이용해 다시 데이터셋2를 만들었어요. 이처럼 데이터셋은 분석하고자 하는 대상에 따라 관점이 달라질 수 있어요.

📦 데이터셋

데이터 과학에서는 데이터만으로 유용한 정보를 얻기 매우 어렵기 때문에, 데이터를 정리해 데이터셋으로 만드는 과정이 꼭 필요해요. 데이터셋은 분석이나 처리를 목적으로 구성된, 구조화된 데이터의 모음이에요.

정형 데이터셋

사전에 정해진 데이터 모델에 맞도록 테이블 형태의 고정된 필드에 저장되는 데이터로 구성돼요.

표가 수천 장으로 늘어난다면? 다산이 보기 쉽게 잘 만든 표도, 시간이 흘러 데이터가 많아지면서 수백 장 또는 수천 장으로 늘어나면 어떻게 될까요? 20세기 후반, 컴퓨터의 발전과 함께 생겨난 방대한 양의 데이터셋을 체계적으로 관리할 필요가 커졌어요. 그래서 등장한 것이 데이터베이스예요.
02

데이터베이스는 무엇일까?

교과서 37~38쪽 · 데이터베이스, 데이터셋과 데이터베이스 비교

쉽게 말하면데이터셋이 수백, 수천 개로 늘어나고 여러 사람이 동시에 써야 한다면, 종이나 파일 하나로는 감당하기 어려워요. 데이터셋을 컴퓨터로 체계적으로 저장해서 여러 사용자가 동시에 꺼내 쓰고 관리할 수 있게 만든 것이 데이터베이스예요.

🗄️ 데이터베이스(database)

데이터를 전자적으로 저장하고 체계적으로 관리하기 위해 구성된 조직화된 데이터의 모음이에요. 데이터셋이 특정 형식으로 정리된 데이터의 집합이라면, 데이터베이스는 컴퓨터로 이러한 데이터셋을 더 효율적으로 저장하고 여러 사용자가 동시에 접근해 데이터를 관리하고 활용할 수 있도록 설계된 데이터 구조예요. 분석이나 연구를 위해 모은 데이터셋이 대량으로 쌓이면, 이를 장기적으로 저장하고 다양한 응용 프로그램에서 쓸 수 있게 구성한 것이 데이터베이스라고 할 수 있어요.

표 Ⅰ-11 데이터셋과 데이터베이스 (교과서 37쪽)

데이터셋구분데이터베이스
특정한 형식으로 구성된 데이터의 집합정의저장과 접근을 컴퓨터로 편리하게 할 수 있도록 체계적으로 구성한 데이터의 집합
일반적으로 데이터 분석이나 연구, 최근에는 기계학습의 훈련을 위해 사용사용일반적으로 조직의 운영을 지원하기 위한 대량의 데이터를 저장하고 관리하는 데 사용
스프레드시트, CSV 파일 등 다양한 형식으로 저장형식텍스트, 숫자, 이미지 또는 기타 유형의 데이터를 포함한 다양한 데이터 유형 저장
더 큰 데이터베이스에서 추출한 데이터의 하위 집합범위여러 데이터셋을 가질 수 있으며 다양한 응용 프로그램에 활용
일반적으로 특정 용도로 사용용도일반적으로 포괄적이고 장기적인 저장과 활용이 목적

주어진 데이터셋에 속성을 추가해 새로운 데이터셋을 만들 수도 있어요.

🎯 데이터셋일까, 데이터베이스일까?

상황을 읽고 표 Ⅰ-11의 정의·사용·형식·범위·용도를 떠올리며 골라요.

🏦 은행의 예금 계좌

여러 사람의 예금 계좌 정보를 모아 놓은 것이 바로 데이터베이스예요. 은행의 예금 계좌 데이터베이스에는 고객, 은행 직원, ATM 기기, 인터넷 뱅킹 등 다양한 사용자가 동시에 접근해 업무를 처리해요. 이렇게 할 수 있는 까닭은 데이터베이스가 있기 때문이에요.

그런데 은행 데이터 처리 작업을 스프레드시트에서 한다면 가능할까요?

03

데이터베이스 관리 시스템은 무엇일까?

교과서 38~39쪽 · DBMS의 역할, 종류, 트랜잭션

쉽게 말하면데이터베이스가 은행 그 자체라면, 데이터베이스 관리 시스템(DBMS)은 예금 계좌 주인이 원하는 입출금 거래나 대출 등을 도와주는 시스템이에요. 사람들은 DBMS를 통해 데이터베이스에 접근해 데이터를 추가·삭제·수정·검색해요.

⚙️ 데이터베이스 관리 시스템(DBMS: Database Management System)

여러 데이터베이스를 가지고 있으면서 다양한 사용자가 요청하는 여러 작업을 처리해 주는 시스템이에요. 여러 데이터셋이 모여 하나의 데이터베이스를 이루고, 이 데이터베이스들을 효율적으로 관리하는 것이 DBMS의 역할이에요.

트랜잭션 데이터베이스 관리 시스템에서 안전성과 일관성을 유지하기 위해 수행되는 일련의 작업이에요. DBMS는 인출 요청부터 현금 지급까지의 과정을 하나의 트랜잭션으로 묶어, 최종 완료 시에만 데이터베이스에 기록해요.

🗂️ 데이터베이스 관리 시스템의 종류 (그림 Ⅰ-7 · 눌러서 펼쳐 보기)

데이터베이스는 관계형 데이터베이스, 문서 데이터베이스, 키-값(key-value) 데이터베이스 등 여러 유형으로 나뉘고, 유형마다 고유한 장단점이 있어 알맞은 응용 프로그램에 쓰여요. 관계형 데이터베이스는 사전 정의된 스키마가 있는 테이블에 구조화된 데이터를 저장하는 데 알맞고, 문서 데이터베이스는 JSON, XML과 같은 문서 형식의 구조화되지 않은 데이터를 저장하는 데 더 알맞아요.

관계형 데이터베이스 관리 시스템

RDBMS: Relational Database Management System. 데이터를 표 형태로 저장하며, SQL(Structured Query Language)을 사용해 데이터를 관리해요.

예) MySQL, PostgreSQL, Oracle

비관계형 데이터베이스 시스템

NoSQL: Not only SQL. 다양한 데이터 구조를 지원하며, 대규모 데이터 처리에 유리해요.

예) MongoDB, Cassandra

클라우드 데이터베이스 시스템

클라우드 환경에서 제공되는 데이터베이스 서비스로, 확장성과 접근성이 좋아요.

예) Amazon RDS, Google Cloud Firestore

이 가운데 1970년대 이후 지금까지 가장 많이 쓰이는 것은 관계형 데이터베이스 관리 시스템이에요. 인터넷이 발전하면서 방대한 데이터를 처리하려고 다른 DBMS도 개발되어 쓰이고 있지만, 여전히 많은 산업 분야에서 관계형 데이터베이스를 활용해요.

낱말 풀이 · 스키마, JSON, XML
  • 스키마 데이터베이스의 구조를 정의하는 설계도예요. 테이블, 열, 관계 등 데이터베이스 요소들의 구성과 제약을 규정해 데이터의 조직과 구조를 설명해요.
  • 제이슨(JSON) 데이터를 저장하고 전달하기 위한 간단한 형식으로, 사람이 읽기 쉽고 컴퓨터가 처리하기 쉬운 텍스트 기반 구조예요. 주로 웹에서 데이터를 주고받을 때 써요.
  • XML 확장 가능한 마크업 언어로, 데이터를 구조화해 저장하고 전달하는 데 쓰는 언어예요.

공문 한 건 한 건 같은 낱낱의 기록이 데이터이고, 이를 분석이나 처리를 목적으로 구조화해 모은 것이 데이터셋이다. 같은 데이터로도 알고 싶은 것에 따라 다른 데이터셋을 만들 수 있다.
데이터베이스는 많은 데이터셋을 컴퓨터로 체계적으로 저장해, 여러 사용자가 동시에 접근하고 장기적으로 활용할 수 있게 구성한 데이터의 모음이다.
데이터베이스 관리 시스템(DBMS)은 데이터베이스를 생성·관리·유지 보수하는 소프트웨어로, 무결성·보안·백업을 맡고 트랜잭션으로 작업을 묶어 안전성과 일관성을 지킨다.
