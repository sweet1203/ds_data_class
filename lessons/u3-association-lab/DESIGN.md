**설계안과 달라진 점**
- 설계안은 연관 규칙 찾기 체험을 「막혔을 때」 안에 두었으나, 핵심 체험이고 질문폼 3번(스스로 해결하기: 구매 항목 바꿔 보기) 근거라서 02에 펼친 카드로 두었다. 「막혔을 때」에는 오렌지3 문제 해결과 「체험에서 같은 조건 만들기」 안내만 둠.
- 0 시작 투표는 「규칙 수 예상」으로 구체화(설계안 「투표」).
- 결과 기록(`arRec`)은 표 한 묶음(`arSet2`·`arN1`·`arTop1`·`arN2`·`arTop2`) + 해석 `arMean`으로 나눴다.

**확인할 점** (화면에서 바로잡음)
- **164쪽 mlxtend `num_itemsets`**(설계안 확인할 점 8): 163쪽 노트북은 `association_rules(..., num_itemsets=len(frequent_itemsets))`, 165쪽 노트북은 이 인자가 없다. 이 인자는 mlxtend 0.23.2에서 생겨 그보다 옛 버전은 TypeError, 0.23.2 무렵 버전은 빼면 오류가 난다(0.25는 기본값 1이 있어 둘 다 됨). 고친 노트북은 `try: … num_itemsets … except TypeError: …` 도우미 `make_rules()`로 두 경우를 다 받게 했다. 코랩 기본 mlxtend 버전은 수업 전에 확인 필요(첫 셀이 버전을 출력함), 그래도 안 되면 맨 끝 설치 셀(`pip install "mlxtend>=0.23.4"`).
- **164쪽 규칙 해석 글의 오류** (화면에 옮기지 않음, 수업 때 주의): 「삼겹살과 콜라를 구매한 고객은 10% 확률로 쌈장도 함께 구매한다(신뢰도 1)」 → 신뢰도 1은 **100%**. 「conviction 값이 무한대(inf)로 … 쌈장을 안 사는 경우가 많다」 → conviction이 무한대인 것은 결과가 틀린 경우가 한 번도 없어서(신뢰도 1)이므로 「쌈장을 안 사는 경우가 **없다**」. 「‘삽겹살’」 오타. 표 머리 「컬럼 설명」의 「데이터에에」 오타.
- **165쪽 「최소 지지도 0.35로 변경하기」는 결과가 0.3과 같다**: 거래가 4개라 지지도는 0.25·0.5·0.75·1뿐이고 0.3과 0.35 사이에 걸리는 집합이 없다(163쪽 7거래 데이터도 0.286·0.429 사이라 같음). mlxtend 0.25로 확인: 0.3·0.35 모두 빈번 집합 9개. 고친 노트북에 「왜 같을까?」 안내와 0.6(집합 4개) 셀을 덧붙였고, 화면 카드는 「결과가 같을까요, 다를까요? 실행하기 전에 예상해 봐요」로 물음.
- **162쪽 규칙 설정 예**: 교과서 본문은 Min. supp. 예 2 %, Min. conf. 예 70 %, Max. rules 예 10,000이고, 161쪽 ows의 실제 값은 minSupport 3, minConfidence 70, maxRules 10000, filterAntecedentMin/Max 1/1000, filterConsequentMin/Max 1/1000, autoFind False(Find Rules를 눌러야 함). 설정 표는 ows 값(3 %)을 쓰고 「162쪽 설명의 예는 2 %」를 적었다. 7거래에서 2 %와 3 %는 결과가 같다(둘 다 「한 번 이상」).
- **161쪽 ows File 설정**: 고객 ContinuousVariable·meta, 상품 여섯 열 DiscreteVariable(값 0, 1)·feature. 그래서 오렌지3는 「상품=0」도 항목으로 다룬다(162쪽 예시 규칙 <삼겹살=1, 식빵=0 → 쌈장=1, 우유=0>). 설정 표에 Type categorical 확인을 넣었다.
- **오렌지3 결과 수(확인 못 함)**: 이 맥의 오렌지3 3.40에는 Associate 애드온이 없어 실제 창은 확인하지 못했다. 화면 체험(=0 포함)의 같은 조건 계산값은 3 %·70 % → 빈번 집합 276개·규칙 1176개(Lift 1위 3.5, 예: 삼겹살=0 → 우유=1), 30 %·70 % → 37개·105개(Lift 1위 1.75), 50 %·70 % → 13개·22개. 파이썬으로 따로 세어 같은 값을 얻었다. 오렌지3가 같은 수를 내는지 수업 전에 한 번 확인 바람(다르면 화면 「막혔을 때」의 「같은 조건」 문장만 고치면 됨). 결과 창의 Supp가 비율인지 개수인지도 확인 필요 — 화면은 「값 그대로 적기」로 두었다.
- 166쪽 역량 키우기 1~3번 문장과 「예」(축구·집·자율 학습 군집)는 옮기지 않고, 「동생에게 설명하듯 + 우리 반을 묶을 기준 + 쓰임」으로 바꿔 물었다. 167쪽 보충·심화의 「사용 위젯」 칸 답(167쪽 ows 위젯 목록)은 화면에 쓰지 않고 앞 차시를 떠올리게 했다.

**계산 확인**: 체험 처음 설정(지지도 0.30·신뢰도 0.20·산 것만) → 빈번 항목 집합 10개, 규칙 14개, 향상도 1위 「삼겹살, 콜라 → 쌈장」·「쌈장 → 삼겹살, 콜라」 1.75 — 교과서 164쪽 출력과 같다. mlxtend 0.25(이 맥, pandas 3.1)로 163쪽 노트북을 실행해 같은 값 확인.
