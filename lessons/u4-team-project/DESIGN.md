퀴즈 11문항(정답 위치 ①3 ②4 ③4, 정답이 가장 긴 보기 4문항). 확장(접기) 내용만으로 푸는 문항은 없다.

질문폼(data-u4-team-project): 1번 ← 01 `why`(~12분), 2번 ← 02 `dataCheck`(~20분), 3번 ← 03 보드 칩과 `bPlan`(~28분).

**설계 보드 점검 규칙** (lesson.js `tpCheck`)
- 질문: 01 `why`가 10자 이상인지.
- 회귀분석: 결과 속성이 숫자(🔢) 또는 집계 숫자(🧮)여야 함. 범주·번호·날짜·깨진 열이면 △.
- 군집·연관분석: 결과 속성은 「없음」이어야 함(고르면 △, 해석할 때 참고하라고 안내).
- 사용할 속성: 결과 속성을 다시 넣음, 번호·이름·주소(🪪), 대부분 비었거나 깨진 열(⚠️), 결과와 거의 같은 정보(스포츠: Value ↔ Release Clause, CLEAN 파일 상관계수 0.983), 집계 속성과 한 행 단위 속성 섞음 → △. k-평균은 범주·날짜 속성 △, 숫자 속성 2개 미만 △.
- 평가 지표: 회귀 ↔ MSE·R², 군집 ↔ 실루엣 계수, 연관 ↔ 지지도·신뢰도·향상도. 어긋나면 △.
- 연관분석을 고르면 세 데이터 모두 「한 거래에 함께 나타난 항목 묶음이 없다」 △(문화 데이터는 예매자를 구별하는 열이 없음).
- ℹ️ 안내: 집계 속성은 Group by로 먼저 만들기, 날짜는 연도·요일로 바꾸기, 주제별 먼저 정할 것(환불 예매·폐업 시설·게임 능력치).
- 주제를 바꾸면 결과 속성·사용할 속성 선택을 지운다(다른 주제의 열이 남지 않게). 「보드 다시 하기」는 칩 4개만 지우고 `bPlan` 글은 남긴다.

**50분 흐름**
- 시작(4분) 모둠 만들기·역할 고르기
- **01(8분, ~12분)** 세 주제 훑고 모둠이 하나 고르기 3분 → 매점 예시 1분 → `why` 3분(질문폼 1번 근거) → 퀴즈 1분
- **02(8분, ~20분)** 점검 카드 읽고 적합/부적합 토의 3분 → 시각화 sorter 2분 → `dataCheck` 2분(질문폼 2번 근거) → 퀴즈 1분
- **03(8분, ~28분)** 보드 고르기·연결 점검·고치기 4분 → `bPlan`·`roles` 3분(질문폼 3번 근거) → 퀴즈 1분
- **04(10분, ~38분)** 다른 모둠과 설계 바꿔 듣기 5분 → 과정 점검·`reflect` 4분 → 퀴즈 1분
- 마무리(10분) key3·오늘의 질문·마무리 퀴즈·질문폼
- 확장(오렌지3로 끝까지)은 남는 시간이나 다음 활동에서 모둠이 함께.

**줄인 것**
- 교과서 195쪽 「④ 모델링 결과를 확인하고 모델 평가하기」와 「⑤ 프로젝트 수행 과정 평가하기」는 실제 분석이 끝나야 할 수 있어, 오늘은 설계 단계의 과정 점검(칩 4개, 교과서 평가 기준을 설계 단계에 맞게 바꿔 씀)으로 대신하고 실제 수행은 04 확장(접기)으로 둠.
- 지도서 예시 답안(선정 이유·데이터 개수·히트맵 분석·k-means 세 그룹·성찰 문장)은 옮기지 않음. 지도서 「데이터 과학 프로젝트 예」(공연 수요 예측 등)도 화면에 쓰지 않음.
- 모둠 이름·준비물 칸은 따로 두지 않고 `roles` 메모에 모둠원·할 일을 함께 씀.
