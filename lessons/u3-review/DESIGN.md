**50분 흐름**
- 시작(4분) 모둠·역할 정하기, 개인정보 안내
- 01(6분, ~10분) 세 방법 다시 보기 → 방법 고르기·`problem` → 퀴즈
- 02(7분, ~17분) 성적표 읽기 → 1/0 표 바꾸기·확인 → `prep` → 퀴즈
- **03(13분, ~30분)** 세 탭 모두 둘러보기 4분 → 우리 방법 탭에서 값 읽기·`result` 4분 → 기술자는 같은 시간에 오렌지3로 모둠 방법의 줄만 만들기(약 8분) → 퀴즈 (질문폼 근거 여기까지)
- 04(8분, ~38분) 몇 모둠만 2분씩 발표(화면에도 안내) → 지킬 점 안내 읽기 → 칩·`reflect`(③ 지킬 점은 질문폼 3번)

**줄인 것**
- 168쪽 수행 계획서(모둠 명·준비물·역할 분담 표)는 역할 칩으로 줄였다. 168쪽 성적표 그림(7명)은 옮기지 않고 지어낸 가상 성적표로 바꿨다.
- 169쪽 평가표(자기·동료 5단계)는 자기 점검 칩(다섯 기준을 쉬운 말로)으로 줄이고, 동료 평가는 발표 때 말로 하게 했다.
- 168쪽 ows의 Gradient Boosting·AdaBoost(회귀 비교), Scatter Plot (1)의 회귀선은 흐름도에서 Linear Regression·Scatter Plot 하나씩으로 줄이고 설정 표에 「함께 이어 비교해도 된다」고 적었다.
- 170쪽 진로 인터뷰는 세 문장으로 줄여 썼다(강사 이름은 쓰지 않음).
- 171쪽 역량 Check!는 넣지 않았다.

**확인할 점**
- **score.csv가 cp949 인코딩**(설계안 확인할 점 9): 오렌지3에서 한글 열 이름이 깨질 수 있다. 선생님이 UTF-8로 다시 저장해 「선생님이 알려 주는 폴더」에 올리기를 권함.
- **실제 친구 성적 수집**: 교과서 168쪽 활동 예는 「친구들이 수강하는 과목과 성적을 수집」이지만, 성적은 민감 정보라 화면은 가상 성적표만 쓰고 시작 화면에 안내했다(교과서 토론 예 「성적은 민감한 정보」와도 맞음).
- **168쪽 ows 설정**(오렌지3 파이썬으로 ows의 위젯 설정을 풀어 확인): Select Columns(회귀) Features 공통과목1 · Target 공통과목2 / Select Columns(군집) Features 공통과목1·2 / Select Columns(연관) Features 선택과목1~6 / Data Sampler 70% / k-Means From 2 to 4, Normalize 켜짐 / Edit Domain 선택과목마다 categorical + 점수 값을 모두 「1」로 매핑 / Association Rules 최소 지지도 2%, 최소 신뢰도 70%. 설정 표는 이 값을 따랐다.
- score.csv는 7명뿐이라 Data Sampler 70%면 훈련 5명·테스트 2명이 된다. 결과 값이 크게 흔들릴 수 있어 화면 안 체험(20명)으로 해석하게 했다.
- 교과서 169쪽 「선택하지 않은 과목이면 숫자 0 또는 비워 두세요」: 화면 02는 0으로 채우게 하고, 오렌지3에서는 비워 두어도 된다고 적었다(Edit Domain 방식은 빈칸 = 결측 = 항목 없음).
- R²(결정 계수)는 이 차시에서 새로 가르치지 않고 앞 차시(129·136~139쪽)에서 나온 값으로만 쓴다. u3-regression-stat·u3-regression-ml이 R²를 「1에 가까울수록 잘 설명」으로 다루는지 총괄 확인 필요.
- 화면 안 k-평균은 정해진 수열로 고른 시작 중심 20벌로 각각 돌려 SSE가 가장 작은 결과를 쓴다(늘 같은 결과). 처음에는 시작 중심 하나로 계산해 k=4·5가 지역 최적(0.49·0.34)이었다. 오렌지3는 정규화·무작위 시작 10번이라 값이 다를 수 있다. 군집·연관 개념은 설계안 u3-clustering·u3-association 표와 pack 교과서 부분만 참고했다.
