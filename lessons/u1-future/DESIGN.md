퀴즈 9문항(정답 위치 ①3 ②3 ③3). 질문폼(data-u1-future) 1번 ← 0 상식 문제 `guess48`·`gapWhy`, 2번 ← 01 머니볼 비교·`relayData`, 3번 ← 02 `jobPick`·`jobComp`·`compHave`·`compGrow`.

**50분 흐름** — 도입(6분) 상식 문제 투표 → 정답 공개, 많은 사람이 틀린 까닭 짝 토의·`gapWhy`, 나의 계획 → 01(9분, ~15분) 전통 vs 머니볼 비교, 지표 카드, 오클랜드 사례, `relayData` → **02(13분, ~28분)** 분야 탭으로 8개 직업 훑기, 역량 칩 2개, 직업 하나 골라 `jobComp` → 03 정리(선택, 12분, ~40분) 맨 위의 도서 대출 정보 통합(잘못된 곳 찾기 → 고치기 → 첫 행 직접 채우기 → 나머지는 직접 또는 한꺼번에 채우기), 접어 둔 분류 게임·출산율 토론은 시간에 따라 → 마무리(8분) 퀴즈·계획 점검·질문폼. 질문폼 근거 활동(0·01·02)은 28분 안에 모두 지나감. 시간이 모자라면 03은 「도서 대출 정보 통합」만 하고 나머지는 과제로.

**줄인 것** — 49쪽 만화 대사는 넣지 않고 줄글로만 설명. 지표 계산 방법은 교과서에 없으므로 다루지 않음(카드에 「계산 방법은 교과서에서 다루지 않아요」 표시). 50~51쪽 직업 사진은 넣지 않음(이모지 탭). 52쪽 역량 키우기 1(비교 서술)은 교과서 문장 대신 분류 게임 + 「데이터베이스가 필요한 까닭」 메모로 바꿈. 53쪽 보충(공개 데이터로 내 도시 데이터셋)·심화(1997년 IMF)는 접어 둔 안내 + 메모 한 칸만. 교과서 51쪽 「주요 개념 정리하기」 문장은 쓰지 않음(마무리 key3는 오늘의 사례를 주어로 새로 씀).

**확인할 점**
- **52쪽 학생 테이블 기본키 중복**: 학생 ID `S002`가 이영준(2학년 1반)·박민수(3학년 2반) 두 명에게 붙어 있음(PDF 43쪽에서 확인). 도서 대출 정보에는 `S003`(진달래꽃)이 있으나 학생 테이블에는 없어, 이대로 VLOOKUP 하면 `S003` 행이 #N/A가 되고 `S002`는 위쪽 이영준 행만 잡힘. 화면에서는 이 오류를 「① 잘못된 곳 찾기 → ② 이대로 통합하면? → ③ 고치기(박민수 = S003)」로 살려 쓰고, 고친 표로 통합함.
- **지도서 141쪽 표와 교과서 표가 다름**: 지도서 쪽 표는 학생 테이블이 S003 박민수로 고쳐져 있고, 도서 대출 정보 넷째 행도 `S003 이방인 2024-05-15~2024-05-20`으로 되어 있음. 교과서(학생용)는 넷째 행이 `S002 이방인`. 화면은 **교과서 표 값**을 쓰고(넷째 행 S002 그대로 → 이영준 2학년 1반), 학생 테이블 박민수만 S003으로 고침(총괄 결정). **그래서 지도서 141쪽 답과 통합 결과가 다름**: 지도서 표로 통합하면 넷째 행이 박민수 3학년 2반이지만, 화면에서는 이영준 2학년 1반이 나옴. 지도서 답으로 채점·설명하지 않도록 주의해 주세요. 학생에게는 「도서 대출 정보에서는 같은 학생 ID가 여러 번 나와도 괜찮다(외래키 역할)」로 설명함.
- 「잘못된 곳 찾기」에서 도서 대출 정보의 S002(두 번)를 누르면 오류가 아니라고 안내함: 대출 테이블의 학생 ID는 학생 테이블 기본키를 가리키는 외래키 역할(41쪽 정의). 대출 테이블 자체의 기본키는 교과서 표에 없음.
- 통합 체험의 함수 모양은 43쪽과 같은 꼴 `=VLOOKUP(A2, 학생!A:D, 2, FALSE)`(시트 이름 「학생」, 열 번호 2·3·4 = 이름·학년·반). 「남은 칸 한꺼번에 채우기」 안내의 「수식을 아래로 복사하면 A2가 A3, A4…로 바뀐다」는 교과서에 없는 스프레드시트 사용법 한 줄임(빼려면 lesson.js `auto` 메시지 삭제).
- 「이대로 통합하면?」의 「S002를 찾으면 위쪽에서 먼저 만난 행의 값만 나온다」는 VLOOKUP의 실제 동작(첫 번째 일치)을 풀어 쓴 것으로, 교과서 43쪽 VLOOKUP 설명(왼쪽 열에서 찾아 같은 행의 값을 가져옴)을 넘어서는 한 문장임.
- 49쪽 지표: 교과서는 OBP(출루율)·SLG(장타율)·OPS(출루율 + 장타율)·WAR(대체 선수 대비 승리 기여도)의 이름만 줌. 카드도 이 범위만 씀(영문 원어·이름 풀이·계산식 없음).
- 48쪽 정답 표기 「③번, 60% 이상」을 화면에서 「③ 60%(60% 이상)」로 씀.
- 48쪽 핵심 질문은 말풍선 「데이터 시대에 우리가 준비해야 할 역량은 무엇일까?」를 오늘의 질문으로 씀.
- 53쪽 「내 계획 점검하기」는 34·48쪽 계획을 함께 점검하라고 함. 34쪽 계획은 다른 차시(u1-database) 메모라 이 화면에서는 「함께 떠올려 봐요」로만 안내.

**지어낸 것(예시 표시)**
- 01 「우리 반 계주 선수를 데이터로 뽑는다면?」 상황(지도서 지도 Tip의 「용돈 인상 요청」 대신 새로 만든 상황).
- 03 분류 게임 6문장(반납 시각 08:42, 도서관 기온 21.5℃, 대출 기록 CSV, 독서 동아리 설문, 학교 도서관 시스템, 전국 공공 도서관 정보)은 새로 만든 상황 문장. 숫자는 예시라 표로 쓰지 않음.
- 퀴즈 2-1(X-ray·MRI 사진 AI)·마무리 1번(「요즘 청소년은 책을 거의 읽지 않는다」)·마무리 2번(학생 ID 기본키)은 교과서 내용으로 만든 새 상황 문장.

**검토 반영(1차)**
- 마무리 key3 2·3번째가 51쪽 「주요 개념 정리하기」와 거의 같아, 오클랜드 어슬레틱스·의료/교통 직업 사례를 주어로 한 새 문장으로 바꿈. 첫 문장도 상식 문제 사례(약 7%)를 주어로 바꿈.
- 마무리 퀴즈 1번이 key3 문장으로 바로 풀려, 「요즘 청소년은 책을 거의 읽지 않는다」는 말을 들었을 때 먼저 할 일을 묻는 적용 문항으로 바꿈.
- 03 정리(선택): 도서 대출 정보 통합을 맨 위로 올리고, 분류 게임·출산율 토론은 `details`로 접음.
- 01 지표 카드: 영문 원어와 이름 풀이를 지움(특히 부정확했던 SLG 풀이). 카드 뒷면이 짧아져 WAR 카드 넘침도 없어짐.
- 0 표지: 투표 전에 「많은 사람이 틀린 문제」라고 알려 주던 문장을 지움(정답 공개 뒤에만 나옴). 「셋 중 아무거나 약 33%」 막대 삭제(총괄 결정).
- 퀴즈 단서 손봄: 2-1 줄기를 「X-ray·MRI 사진」으로 바꾸고 보기 길이를 맞춤(에듀테크 데이터 사이언티스트를 오답으로). 1-1·1-2·1-3·2-3은 정답만 길거나 짧지 않게 오답을 바꿈. 정답 위치 ①3 ②3 ③3 유지.
- 통합 위젯 ① 「찾은 횟수」 → 「누른 횟수」. 「한꺼번에 채우기」 버튼은 유지(총괄 결정).
- 분류 게임 카드에 `short`(판에 쌓이는 짧은 이름)를 넣음. 마무리 `planCheck`·`planNew`의 저장 표시(.saved)를 각 메모 칸 안으로 옮김.
- 투표·칩 기록: `vote()`·`chips()`는 `MEMO`에 저장하고, 저장 키 `MK`가 `ds-u1-future-memo` + `WHO.sfx`(학번 `@12345`)라 학번별로 따로 저장됨을 확인함. 진도 주소(`progressEndpoint`)가 비어 있으면 `sfx`가 빈 값이 되어 기기 하나에 하나만 저장되는데, 이는 공통 틀의 동작이라 고치지 않음.

**검토 반영(2차)**
- 메모 모아 보기에서 「(선택)」 항목은 쓴 것만 보이게 함(lesson.js에서 `MEMOLIST`를 걸러 `memoSummary`에 넘김, u1-attributes와 같은 방식).

- 마무리 분량: 계획 점검 2칸 중 「새롭게 알게 된 점」을 (선택)으로.
