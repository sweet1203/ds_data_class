퀴즈 14문항(정답 위치 ①5 ②5 ③4). 질문폼(data-u1-relational) 1번 ← 01 중복 찾기·02 중복의 문제점·`planRel`, 2번 ← 02 외래키 따라가기·`fkNote`, 3번 ← 03 VLOOKUP·`vlookNote`. SQL(04)은 질문폼 근거로 쓰지 않음.

**50분 흐름** — 시작(3분) 메멘토·다산 연결, `planRel` → 01(7분) 정의, 칼럼·레코드 눌러 보기, 중복 찾기 → 02(7분, 17분 무렵 끝) 문제점, 외래키 따라가기, `fkNote`(기본키 지키기는 선택) → **03(17분 무렵 시작, 11분)** 통합의 필요성 카드 하나만 읽고 바로 VLOOKUP 체험(19분 무렵 닿음, 지시문 순서대로 ① 한 줄 3칸 직접 → ② 행 섞기 → ③ 순서대로 붙여넣기와 비교 → 나머지 한 번에), `vlookNote`(28분 무렵 끝), 접힌 이점·방법 카드는 시간이 있으면 → 마무리(9분) 퀴즈·질문폼 → 남는 시간(약 8~10분) 04 SQL(선택). 질문폼 근거 활동은 모두 30분 안에 닿음. 04는 「(선택)」 화면이고 첫머리에 「마무리로 가기」 단추를 둠(지도서 135쪽 「SQL 명령어 실습은 학생 수준이나 현장 상황에 따라 선택적으로」).

**줄인 것** — 44쪽 메멘토는 표지 이야기와 한 칸 요약으로만. 42쪽 그림 Ⅰ-9·Ⅰ-10(사이트 화면)은 넣지 않고 사이트 이름만(주소 없음). 41쪽 만화는 말풍선 글만. 43쪽 「주요 개념 정리하기」 문장은 key3에 그대로 옮기지 않고 새로 씀. 46쪽 myCompiler 실습 사이트 안내는 화면 안 실습기로 대신함(외부 주소 없음). ALTER·DROP은 카드 설명만(실습기에서 직접 써 볼 수는 있음). GRANT·REVOKE·COMMIT·ROLLBACK(과 TRUNCATE)은 카드 설명만 두고, 실습기에서 입력하면 「이 실습기(SQLite)에서는 지원하지 않는 명령이에요」라고 안내하고 실행하지 않음. 성취도 평가 체크 칸은 넣지 않음.

**확인할 점**
- 40·46쪽 「옷데 시청1관/2관」은 「롯데 시청」의 오타(41쪽은 「롯데」) → 화면·SQL 모두 「롯데」.
- 배우 이름이 40·41·46쪽 INSERT는 「매듀 매커니히」, 47쪽 결과 표는 「매튜 메커니히」(PDF 38쪽에서 직접 확인) → 화면은 40·41쪽 표기 「매듀 매커니히」로 통일.
- 46쪽 CREATE의 칼럼 이름 「주연 배우_이름」은 띄어쓰기가 있어 MySQL에서는 오류, SQLite에서는 칼럼 이름이 「주연」이 되어 버림 → 「주연_배우_이름」으로 고치고 화면 `details`에 적음.
- 46쪽 타이타닉 INSERT의 닫는 따옴표(`'액션‘`)와 47쪽 `WHERE 장르 = ‘SF’`, UPDATE·DELETE의 따옴표가 굽은 따옴표 → 곧은 따옴표로 고침. 실습기는 학생이 굽은 따옴표를 쓰면 알려 주고 바꿔 줌.
- **타이타닉 장르(총괄 확인: 이 흐름 유지)**: 46쪽 INSERT에서 「액션」으로 넣고, 47쪽 「데이터 수정」 UPDATE가 바로 이 값을 40쪽 표와 같은 「로맨스」로 고치는 흐름이라 의도된 값으로 보임(47쪽 추가 후 결과 표도 「액션」). 그래서 설계안 4번과 달리 ②에서는 「액션」으로 넣고 ⑥ UPDATE로 고치게 둠(②·⑥ 설명에 적어 둠). 처음부터 「로맨스」로 넣으려면 lesson.js `STEPS[1]`의 마지막 줄 장르만 바꾸면 되지만, 그러면 ⑥이 아무것도 바꾸지 않음.
- 47쪽 그래비티의 장르 「로맨스」는 실제 영화와 다르지만 「가상의 영화 데이터」이므로 **교과서대로 「로맨스」**(총괄 결정). ⑤ WHERE 결과는 교과서와 같은 2줄.
- 41쪽 관계형 데이터베이스 예시는 영화 한 편에 상영관 하나만 연결되어 있어, 40쪽 그림 Ⅰ-8의 「DGV 강남2관」·「롯데 시청2관」 레코드는 나뉜 테이블로 다시 만들 수 없음(지도서 135쪽도 「관계형 데이터베이스의 구조를 완전히 반영한 것은 아니며」라고 함). 화면에서는 교과서 예시 그대로 두고, 「영화 ID를 누르면 그림 Ⅰ-8의 레코드와 같은 내용」이라고만 씀.
- 43쪽 ❷ 통합 결과 그림의 바람 열(10·9·9·11·9)은 강수량 값이 잘못 들어간 것 → 출판사 정오표대로 10·11·8·11·7. 원본 xlsx(`데이터 통합.xlsx`)의 교통사고 시트 A6 날짜가 20240924가 아니라 **20240923**(중복)으로 되어 있음 — 학생에게 파일을 나눠 줄 일이 생기면 고쳐야 함. 원본 날씨 시트의 행 순서는 교통사고 시트와 같아서, 화면에 「날씨 시트 행 섞기」를 두어 VLOOKUP의 의미를 보여 줌.
- 45쪽 측주 「RDMBS」는 「RDBMS」의 오타. 화면은 RDBMS로만 씀.
- `FALSE`의 뜻은 교과서에 풀이가 없어, 지도서 133쪽을 근거로 수식 줄 아래 한 줄(「정확히 일치하는 값을 찾아요」)로만 풀어 씀.

**지어낸 것(예시 표시)**

## 검토 반영(1차)
- **30분 규칙**: 03의 이점·통합 방법·고려 사항을 VLOOKUP 뒤 접힌 카드로 옮겨, VLOOKUP에 19분 무렵 닿게 함. VLOOKUP 지시문에 「① 한 줄(3칸) 직접 채우기 → ② 날씨 시트 행 섞기 → ③ 순서대로 붙여넣기와 비교」 순서를 밝힘(질문폼 3번 근거). 02 「기본키 지키기」에 (선택) 표시.
- **그래비티 장르**: 총괄 결정에 따라 교과서대로 「로맨스」로 되돌림(⑤ 결과 2줄, 교과서와 같음). 타이타닉 「액션」 → ⑥ UPDATE 흐름은 그대로. 화면 `details` 문구도 고침.
- **퀴즈**: 3-1 줄기가 43쪽 「주요 개념 정리하기」 셋째 문장과 같아, 급식 만족도 설문과 메뉴표를 날짜로 맞춰 모으는 새 상황 문장으로 바꿈. 1-3 오답 「암호화」(안 배운 말) → 「백업」. 5-1 오답 「칸을 숫자로만 채우려고」의 「만」을 뺌.
- **SQL 실습기**: GRANT·REVOKE·COMMIT·ROLLBACK·TRUNCATE를 입력하면 「이 실습기(SQLite)에서는 지원하지 않는 명령이에요」 안내(카드 아래에도 한 줄). 이미 실행한 ②·④를 다시 실행하면 「이미 넣었어요. 한 번 더 넣으면 같은 레코드가 또 생겨요」와 「그래도 실행」 단추. 실행기를 불러오기 전 「처음부터 다시」가 「새로 만들었어요」라고 잘못 안내하던 것을 고침. 불러오기 실패 안내를 원인에 따라 나눔(파일·미리 보기로 열었을 때는 「수업 사이트 주소로 열어야 실습기가 떠요」, 사이트에서 실패하면 네트워크 안내). 입력에 「주연 배우_이름」(띄어쓰기)이 있으면 실행 전에 알리고 붙여 쓰기로 바꿔 줌.
- **기본키 지키기**: 다른 칸을 누르면 입력값이 지워지던 문제를 고침(입력값을 상태로 보관). 새 행을 escape된 값으로 저장해 비교하던 버그를 고쳐, 원문으로 저장·비교하고 화면에 그릴 때만 escape함.
- **VLOOKUP**: 수식 줄 아래에 「A2 찾을 값 · 날씨!A:D 찾을 표 · 2 가져올 열 번호 · FALSE 정확히 일치하는 값을 찾아요」 한 줄(지도서 133쪽 근거). 확인할 점의 「FALSE 풀이 없음」 항목은 이 반영으로 해소.
