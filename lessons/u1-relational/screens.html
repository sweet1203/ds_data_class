01

관계형 데이터베이스란 무엇일까?

교과서 40쪽 · 관계형 데이터베이스, 테이블(관계), 칼럼, 레코드

쉽게 말하면관계형 데이터베이스는 데이터를 표(테이블)로 저장하고, 표와 표 사이의 관계로 데이터를 엮어 관리하는 방식이에요. 표의 세로줄은 칼럼, 가로줄은 레코드라고 불러요.

🧩 관계형 데이터베이스(RDB: Relational Database)

데이터를 테이블의 형태로 저장하고, 이러한 테이블 간의 관계를 통해 데이터를 구성하고 관리하는 방식이에요. 데이터의 중복을 최대한 없애고 데이터 사이의 관계를 잘 정의해서, 데이터의 생성·수정·삭제가 효율적으로 이루어지도록 설계한 모델을 관계형 모델이라고 해요. (관계형 데이터베이스는 E. F. Codd 박사가 1970년대에 처음 제시했어요.)

관계형 데이터베이스 시스템은 관계형 데이터베이스를 처리·유지·관리하며, 사용자가 데이터를 효율적으로 쓸 수 있도록 지원해요.

🎬 영화 상영 정보 테이블 (그림 Ⅰ-8을 다시 그림 · 가상의 영화 데이터)

칼럼

테이블 안에 세로로 묶인 값들. 영화 제목, 감독 이름 같은 칼럼이 있어요.

다른 말로 열, 필드, 속성이라고도 하고, 인공지능 분야에서는 특성이라고도 해요.

레코드

각 칼럼의 값들을 가로로 묶은 것. 영화 한 편의 상영 정보 한 줄이에요.

행(row) 또는 튜플이라고도 불러요.
표 형식으로 된 전체 데이터는 테이블 또는 관계(relation)라고 불러요. 이 테이블은 잘 저장된 것처럼 보이지만, 자세히 보면 전체 칼럼에 중복이 많아요. 레코드가 5개 정도면 큰 문제가 없어 보여도, 데이터가 많아지면 중복 때문에 처리와 관리가 어려워져요.
02

관계형 데이터베이스는 어떤 구조일까?

교과서 41쪽 · 중복의 문제점, 기본키, 외래키

쉽게 말하면모든 것을 한 표에 넣는 대신 주제별로 표를 나누고, 표마다 행을 하나씩 구분하는 번호(기본키)를 붙여요. 그리고 다른 표의 번호를 적어 두는 칸(외래키)으로 표와 표를 이어요.

➕ 칼럼을 계속 추가하면?

그림 Ⅰ-8 테이블에 영화 제작 국가 정보가 필요하다면 칼럼을 추가하면 돼요. 그런데 필요할 때마다 칼럼을 추가하다 보면 테이블이 엄청나게 커지고 중복도 많아질 수 있어요.

「상영관 좌석 수도 추가해 줘.」「상영 시간 칼럼도 추가해 줘.」「영화 제작 국가 칼럼도 추가해 줘.」

중복의 문제점

  • 데이터 일관성 문제
  • 데이터 품질(신뢰성) 및 성능 저하
  • 저장 공간 낭비
  • 데이터 관리 비용 증가
  • 데이터 복구 및 백업 시간 증가

관계형 데이터베이스는

중복을 제거한 테이블로 데이터를 저장하고, 각 테이블은 특정 주제나 개체에 대한 정보만 담아요. 또 테이블을 연결해 새로운 정보를 만들고 효율적으로 관리해요.

🔗 외래키 따라가기 (41쪽 관계형 데이터베이스 예시)

가운데 영화 테이블에서 외래키 칸(감독 ID, 배우 ID, 장르 ID, 상영관 ID)을 누르면 그 값이 가리키는 테이블의 행으로 따라가요. 영화 ID를 누르면 네 개의 외래키를 한꺼번에 따라가 상영 정보 한 줄을 다시 만들어요.

🔑 기본키

각 테이블 안에서 데이터를 고유하게 식별하는 키예요. 중복되는 값이 없어야 해요.

🧷 외래키

다른 테이블의 키를 참조하는 키로, 테이블 간의 관계를 연결해요. 영화 테이블의 감독 ID·배우 ID·장르 ID·상영관 ID는 각 테이블의 기본키를 참조하는 외래키예요.

이런 방식으로 중복 문제를 해결하면 데이터의 중복을 최소화하고 데이터 관리의 효율성을 높일 수 있어요.

03

데이터 통합은 왜 필요할까?

교과서 42~43쪽 · 데이터 통합의 필요성과 방법, VLOOKUP

쉽게 말하면문제를 풀려고 여러 곳에서 모은 데이터는 대개 따로따로 있어요. 날씨는 날씨대로, 교통사고는 교통사고대로요. 이것을 공통된 기준(예: 날짜)으로 한곳에 모아야 함께 분석할 수 있어요. 이것이 데이터 통합이에요.

🔗 데이터 통합

데이터 통합은 다양한 소스의 데이터를 한곳에 모아 사용자가 효율적으로 분석하고 활용할 수 있게 하는 과정이에요. 데이터는 파일이나 데이터베이스 관리 시스템으로 잘 관리되지만, 새로운 문제를 해결하거나 인공지능 시스템을 만들 때 필요한 데이터가 한곳에 모여 있지 않을 가능성이 높아요.

🌦️ 날씨 정보‘기상청 기상자료개방포털’에서 날짜별 날씨를 찾아요.
+
🚗 교통사고 정보‘공공데이터포털’에서 도로교통공단 사망 교통사고 정보를 따로 찾아요.
→
🧹 전처리 · 통합원하는 형태로 다듬어 날짜별 날씨와 사상자 수를 한 데이터셋으로 모아요.

예: 날씨에 따른 교통사고 사상자 수를 분석하거나 예측하는 인공지능 시스템을 만들려면 두 정보가 함께 담긴 데이터셋이 필요하지만, 이런 데이터셋을 한꺼번에 구하기는 쉽지 않아요.

📗 스스로 해결하기 · VLOOKUP으로 두 시트 통합하기 (43쪽 · 탐구 · 실습)

서로 다른 곳에서 모은 가상의 두 데이터셋이 스프레드시트의 교통사고 시트와 날씨 시트에 있어요. 교통사고 시트를 기준으로 날씨 정보를 붙여 데이터 통합 시트를 만들어요.

  1. 한 줄(3칸) 직접 채우기 — 통합 시트의 노란 빈칸을 누르고, 날씨 시트에서 몇 번째 열을 가져올지 골라요.
  2. 날씨 시트 행 섞기 — 이미 채운 값이 그대로 맞는지 봐요.
  3. 순서대로 붙여넣기와 비교 — 날짜로 찾지 않으면 어떻게 되는지 봐요. 그다음 남은 칸 모두 채우기로 마무리해요.

VLOOKUP 함수: 지정한 값을 표의 왼쪽 열에서 찾은 뒤, 같은 행에 있는 다른 열의 값을 가져오는 함수예요.

🧭 데이터 통합의 이점과 통합하는 방법 (42~43쪽 · 눌러서 펼쳐 보기)

데이터 통합의 이점

종합적인 시야

하나의 통합된 시스템에서 다양한 데이터를 분석해 더 나은 의사 결정을 더 빨리 내릴 수 있어요.

비용 절감 · 효율성 향상

수동 작업을 자동화해 시간과 노동 비용을 크게 아낄 수 있어요.

데이터 접근성 증가

모든 구성원이 필요한 데이터에 쉽게 접근해 공평하게 데이터를 활용할 수 있어요.

데이터를 통합하는 방법

🗄️

한 데이터베이스에 모으기

데이터베이스 관리 시스템으로, 다양한 경로로 모은 데이터를 하나의 데이터베이스에 집중해 통합해요.

🌐

나눠 저장하고 필요한 것만 모으기

데이터를 물리적으로 서로 다른 위치에 분산해 저장하면서, 필요한 통합 정보만 모아 써요.

📗

스프레드시트로 통합하기

데이터 양이 아주 크지 않다면 스프레드시트로 간단하게 통합할 수 있어요.

통합할 때 생각할 점 데이터 크기가 커져 처리에 부담이 될 수 있고, 통합 과정에서 오류가 생길 수 있어 주의해야 해요. 상황에 맞게, 데이터 양과 데이터 내용이 바뀌는 빈도에 따라 알맞은 통합 방식을 골라요.
04

(선택) SQL 명령어로 데이터베이스 다루기

교과서 45~47쪽 · SQL, DDL, DML, DCL, TCL, CREATE, INSERT, SELECT, WHERE

선택 화면이에요. 시간이 남거나 더 해 보고 싶을 때 해요. 질문폼은 다음 화면(마무리)에 있어요.
쉽게 말하면SQL은 관계형 데이터베이스에게 「표를 만들어」, 「이 값을 넣어」, 「이런 것만 보여 줘」라고 말하는 언어예요. 명령 한 줄을 실행하면 데이터베이스가 바로 답해요.

💬 SQL(Structured Query Language)

관계형 데이터베이스 관리 시스템(RDBMS)에서 데이터를 관리하고 조작하는 데 가장 널리 쓰이는 표준 언어예요. 데이터를 검색·삽입·수정·삭제하고, 테이블 간의 관계를 정의하고 처리할 수 있어요. 각 테이블은 행(레코드)과 열(필드)로 이루어지고, SQL로 여러 테이블을 연결하고 데이터를 조작해요.

데이터 정의 언어(DDL)데이터를 저장하려고 데이터베이스 구조, 테이블 등을 정의할 때CREATE 새 테이블 또는 데이터베이스를 생성ALTER 기존 테이블의 구조를 변경DROP 테이블이나 데이터베이스를 삭제
데이터 조작 언어(DML)효율적인 관리를 위해 테이블의 데이터를 다룰 때SELECT 데이터를 조회INSERT 새 데이터를 삽입UPDATE 기존 데이터를 수정DELETE 데이터를 삭제
데이터 제어 언어(DCL)무결성을 위해 사용자 권한을 관리할 때GRANT 사용자에게 특정 권한을 부여REVOKE 사용자 권한을 취소
트랜잭션 제어 언어(TCL)일관성을 위해 트랜잭션을 관리할 때COMMIT 트랜잭션을 확정해 영구적으로 적용ROLLBACK 트랜잭션을 취소해 원래 상태로 되돌림

SQL은 국제 표준(ISO/IEC)으로 정해져 있어 MySQL, PostgreSQL, Oracle, SQL Server 등에서 쓸 수 있지만, 데이터베이스마다 고유한 확장 SQL을 제공하기도 해요. 이 화면의 실습기는 SQLite라는 데이터베이스를 브라우저 안에서 돌려요.

ℹ️ 데이터 제어 언어(GRANT·REVOKE)와 트랜잭션 제어 언어(COMMIT·ROLLBACK)는 이 실습기(SQLite)에서는 지원하지 않는 명령이에요. 아래에서는 CREATE, INSERT, SELECT, UPDATE, DELETE를 실습해요.

  • 교과서 46~47쪽의 일부 따옴표가 굽은 따옴표(‘ ’)로 인쇄되어 그대로 실행하면 오류가 나요. 실습기에서는 곧은 따옴표(')로 고쳤어요.

관계형 데이터베이스는 데이터를 테이블(관계)로 저장하고 테이블 사이의 관계로 데이터를 관리한다. 세로로 묶인 값은 칼럼, 가로로 묶인 값은 레코드다.
한 테이블에 모든 정보를 담으면 중복이 늘어난다. 그래서 주제별 테이블로 나누고, 행을 고유하게 구분하는 기본키와 다른 테이블의 키를 참조하는 외래키로 테이블을 잇는다.
데이터 통합은 여러 곳에서 모은 데이터를 공통된 기준으로 한곳에 모아 분석할 수 있게 하는 과정이다. 스프레드시트에서는 VLOOKUP으로 기준 값을 찾아 같은 행의 값을 가져올 수 있다.

질문폼에 내 생각 쓰기

  1. 영화 상영 정보 테이블(그림 Ⅰ-8)에서 중복을 찾아보았습니다. 같은 값이 반복되는 테이블에 정보를 계속 추가하거나 값을 고칠 때 생길 수 있는 문제를 쓰고, 관계형 데이터베이스가 이 문제를 어떻게 줄이는지 설명하세요.
  2. 「외래키 따라가기」에서 영화 테이블의 ID를 눌러 다른 테이블의 값을 찾아보았습니다. 기본키와 외래키가 무엇인지 예를 들어 설명하고, 나뉘어 있는 테이블에서 영화 한 편의 상영 정보를 어떻게 다시 읽을 수 있는지 쓰세요.
