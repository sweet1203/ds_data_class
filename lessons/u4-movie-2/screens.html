(확장) 두 워드 클라우드의 낱말 빈도 합쳐 보기 · 교과서 204~205쪽

지난 시간 고관객군·저관객군 Word Cloud를 만들었다면, 두 워드 클라우드가 내보내는 Word Counts(낱말별 나온 횟수 표)를 합쳐 한 산점도에 그려 볼 수 있어요. Text 애드온이 필요해요.

  1. Merge Data (Transform)

    고관객군 Word Cloud의 Word Counts → Data, 저관객군 Word Cloud의 Word Counts → Extra Data. 두 표를 Word끼리 맞추고, 두 표에 모두 있는 낱말만 남겨요(Find matching pairs of rows). 같은 이름의 열은 Word Count (1), Word Count (2)로 바뀌어요.

  2. Select Rows (Transform)

    Word Count (1) is greater than 10, Word Count (2) is greater than 10 두 조건으로 두 묶음 모두에서 자주 나온 낱말만 골라요.

  3. Edit Domain (Data)

    Word 속성의 Type을 Categorical로 바꿔요. 글(text) 속성은 산점도의 Label로 쓸 수 없어서예요.

  4. Scatter Plot (1) (Visualize)

    x: Word Count (1)(고관객군), y: Word Count (2)(저관객군), Label: Word. 대각선에서 x 쪽으로 멀리 떨어진 낱말이 고관객군 리뷰에서 상대적으로 자주 나온 낱말이에요.

저관객군 리뷰가 고관객군보다 두 배쯤 많아서 점들이 y 쪽으로 치우쳐 보여요. 낱말 하나를 골라 리뷰 100개당 횟수로 바꿔 견주면 더 공정해요. 이 그림으로도 흥행의 원인은 알 수 없어요. 교과서 205쪽 해 보기처럼 다른 시각화를 하나 골라 그려 봐도 좋아요.

02

관객 수 예측 평가실

교과서 207쪽 · 실젯값과 예측값 · MSE · RMSE · MAE · MAPE · R²(결정 계수)

쉽게 말하면평가 지표는 실젯값과 예측값이 얼마나 다른지를 여러 방식으로 요약한 숫자예요. 같은 예측도 어떤 지표로 보느냐에 따라 좋아 보이기도, 아쉬워 보이기도 해요. 직접 값을 바꿔 가며 지표가 어떻게 움직이는지 봐요.

📏 평가 지표 다섯 가지

MSE

(실젯값 − 예측값)을 제곱해 평균한 값. 제곱하므로 큰 오차에 민감해요. 단위도 제곱(명²)이 돼요.

RMSE

MSE의 제곱근. 오차를 원래 단위(명)로 나타내 해석하기 쉬워요.

MAE

오차의 절댓값을 평균한 값. 오차의 절대적 크기를 나타내요.

MAPE

|오차| ÷ 실젯값을 평균한 값(백분율로 읽기도 해요). 0에 가까울수록 정확해요. 실젯값이 0이면 나눌 수 없어요.

R² (결정 계수)

실젯값의 흩어짐 가운데 모델이 설명한 몫. 1에 가까울수록 성능이 좋아요. 「몇 % 맞혔다」는 뜻은 아니에요.

🧮 평가실 · 지표를 직접 계산해 보기 (지어낸 예시 영화 8편, 단위 만 명)

실젯값·예측값 칸을 눌러 숫자를 바꿔 보세요. 0~700 사이 값이 그림에 보여요.

🔍 해 보기 ① 예측 A와 예측 B를 눌러 다섯 지표를 견줘요. ② 모두 평균으로를 누르면 R²가 얼마인지 봐요. ③ 가 영화 실젯값 2로를 누르면(예측 A 기준으로 바뀌어요) 어떤 지표가 크게 변하나요? ④ 실젯값 하나를 0으로 바꾸면 MAPE는 어떻게 되나요?

Regularization(정규화)

Ridge regression(L2)은 계수의 제곱을 더하는 방식으로 과적합을 막고, Lasso regression(L1)은 계수의 절댓값을 더해 덜 중요한 계수를 0으로 보내요. Elastic net은 둘을 절충해요. 오늘은 No regularization으로 해요.

이름이 같은 두 「정규화」

여기의 정규화는 모델 계수에 벌점을 주는 방법이에요. 데이터 값을 0~1 범위로 바꾸는 데이터 정규화와는 다른 일이에요.

(선택·확장) 파이썬 웹크롤링 코드 읽어 보기 · 교과서 208쪽

영화 데이터셋의 평점·참여자 수·리뷰는 영화명으로 검색한 웹 페이지에서 모은 것이에요. 선생님이 알려 주는 노트북에서 코드를 읽으며 흐름만 살펴봐요.

  1. 라이브러리

    requests는 웹 페이지를 요청해 가져오고, BeautifulSoup은 HTML 문서에서 원하는 부분을 찾아 주며, urllib.parse는 주소 속 한글을 인코딩해요. re는 정규 표현식으로 글자에서 숫자만 남길 때 써요.

  2. 요청 보내기

    영화 이름으로 검색 주소를 만들고 requests.get()으로 요청해요. 응답 코드가 200이면 성공이에요.

  3. 원하는 정보 찾기

    soup.find_all()로 평점·참여자 수·리뷰가 들어 있는 태그를 찾아 글자를 꺼내요. 영화당 평론가 리뷰는 10개까지 모아요.

⚠️ 웹크롤링 전에 꼭 확인해요. 사이트의 robots.txt(수집해도 되는 곳을 알리는 파일)와 이용 약관을 확인하고, 짧은 시간에 요청을 많이 보내 서버에 부담을 주지 않아요. 개인정보는 모으지 않고, 공식으로 제공하는 데이터나 공공 데이터가 있으면 그것을 먼저 써요. 사이트 구조가 바뀌면 코드가 찾는 태그 이름이 달라져 그대로는 동작하지 않을 수 있어요. 실제 사이트에 요청을 보내는 셀은 선생님 안내 없이 실행하지 않아요.

관객 수 모델에 넣은 참여자 수·상영 횟수는 개봉 뒤에 쌓이는 기록이라, 이 모델은 개봉 전 예측이 아니라 상영한 영화의 관객 수 추정에 가깝다. 상영 횟수 하나를 빼도 평점·참여자 수가 남아 마찬가지다.
평가실에서 R²가 0.97이어도 MAPE는 0.21이었고, 작은 영화 하나의 실젯값만 바꿔도 MAPE가 크게 흔들렸다. 지표마다 보여 주는 면이 다르다.
영화 143편을 8:2로 나눠 본 적 없는 영화 28편으로 평가했더니, 리뷰 줄로 나눈 교과서 그림과 다른 숫자가 나왔다. 무엇을 한 줄로 삼았는지가 평가를 바꾼다.
